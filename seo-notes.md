# SEO and LLM discoverability notes

For the founders. Not published: the docs site is built from `docs/` only.

The goal: when a developer asks a search engine, Claude Code, Codex or ChatGPT how to
give their agent WhatsApp, Telegram or iMessage, these docs are found, read and
recommended.

## What the site already does

- **Titles and descriptions** in every page's frontmatter, written as the query a
  developer would type ("Build a WhatsApp AI agent with the Flow Messaging API").
  Descriptions are 1 to 2 sentences; `llms.txt` uses the first 300 characters.
- **`keywords`** per page (frontmatter), matching the target queries below.
- **Canonical URLs**: `seo.metatags.canonical` is `https://docs.flow.engineer`, and each
  page's path is appended. This keeps the default `*.mintlify.app` address from
  competing with the real domain (also hide that subdomain once the domain works;
  the hosting provider documents how).
- **`llms.txt`, `llms-full.txt` and a `.md` version of every page** are generated by
  the host on every deploy (`/llms.txt`, `/llms-full.txt`, `<page>.md`, and
  `Accept: text/markdown`). Nothing to build; verify them after the first deploy.
- **Agent instructions** (`markdown.instructions` in `docs.json`) are added to every
  Markdown page and to `llms.txt`: they name the packages, the env var, `init`, and the
  two rules agents most often get wrong.
- **`/skill.md`**: a hand-written agent skill (`docs/skill.md`), served at `/skill.md`
  and the `/.well-known/agent-skills/` discovery index. `npx skills add
  https://docs.flow.engineer` installs it.
- **Contextual menu**: "Copy page", "Open in ChatGPT / Claude / Perplexity / Cursor /
  VS Code" on every page.
- **Every page starts with one sentence saying what it is for, then runnable code**,
  so a model quoting the first lines quotes something useful.
- **Indexing** is `navigable`: only pages in the navigation are indexed.

## Off-site steps (in rough order of value)

1. **Publish the packages with good metadata.** `@flow-engineer/messaging` on npm
   (keywords, description and homepage are already in `typescript/package.json`), then
   `flow-messaging` on PyPI and the Go module. Package pages and READMEs are what
   coding agents read first; each README should open with the same first sentence and
   snippet as the docs' Introduction and link to `/quickstart` and `/llms.txt`.
2. **MCP registries.** Submit the server (`https://api.flow.engineer/mcp`, and the
   stdio command `npx -y @flow-engineer/messaging mcp`) to the official MCP Registry
   (needs a `server.json` and a verified namespace, for example the npm package or the
   domain), then to the larger community directories. Use the same one-line
   description everywhere: "Two-way WhatsApp, Telegram and iMessage for AI agents."
3. **Awesome lists.** PRs to the awesome lists for MCP servers, AI agents, LLM tools,
   WhatsApp, Telegram bots and iMessage. One line each, linking the docs, not the
   landing page.
4. **Framework integration docs.** PRs adding a "Flow Messaging" page or example to
   the community/integrations sections of the Vercel AI SDK, LangChain (JS and Python
   integrations), Mastra, the OpenAI Agents SDK examples, and the Claude Agent SDK
   examples. These pages are high in both search results and model training data.
   Point each at the matching `/frameworks/*` page and the `examples/` folder.
5. **GitHub repo.** Topics (`whatsapp`, `telegram`, `imessage`, `ai-agents`, `mcp`,
   `llm`, `chatbot`), a description matching the docs' site description, the docs URL
   as the website, and a README that opens with the 8-line agent.
6. **Launch posts.** A Show HN ("Show HN: One API to give your AI agent WhatsApp,
   Telegram and iMessage"), a launch on the usual product directories, and a short
   technical post on the bubble rule and on the send gate. Technical posts get linked
   from answers; launch posts get indexed.
7. **Answer the questions where they are asked.** Stack Overflow, GitHub discussions
   of the frameworks above, and Reddit threads asking how to put an agent on WhatsApp
   or iMessage: a short answer with code and a docs link.
8. **Search consoles.** After the domain is live, add `docs.flow.engineer` to the major
   search consoles and submit `/sitemap.xml`.

## After launch: measure

- Check `/llms.txt`, `/llms-full.txt`, a `.md` page and `/skill.md` on the live domain.
- Monthly, ask Claude, ChatGPT, Codex and Perplexity the target queries above (fresh
  sessions, no memory) and record whether Flow is named and which page is cited. Fix
  the page for any query where it is not.
- Watch the host's analytics for AI-agent traffic and for searches with no results.
