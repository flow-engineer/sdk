## Messaging (Telegram, iMessage): Flow Messaging

This project talks with people on Telegram and iMessage through Flow
Messaging (`@flow-engineer/messaging`, API at https://api.flow.engineer, docs at
https://flow.engineer/docs/unified-messaging-api). The key is `FLOW_MESSAGING_KEY` in `.env` (`fk_test_` keys
reach only the sandbox: a person opens the sandbox link and taps Start, or sends the
sender's `join_code` message, such as `Hi Sandbox app (ref wild-otter-04508705)`).

Check for `FLOW_MESSAGING_KEY` (environment or `.env`) first; never get a second key when you have one. No key yet? Get a test key with no account, in one call: `curl -X POST https://api.flow.engineer/v0/sandbox/keys`, then save `key` as `FLOW_MESSAGING_KEY` and `claim_token` as `FLOW_CLAIM_TOKEN` (both shown once) in a git-ignored `.env`. Or run `npx @flow-engineer/messaging init`: it does the same and prints the sandbox link and join message, then asks before installing agent files or the MCP server. That answer is the project owner's, so never pass `--yes` for them. Never invent or hard-code keys.

Sandbox allowance: without an account, 1 contact and 50 messages in total on the Telegram sandbox (WhatsApp's when it opens), and the key expires after 7 days. Claimed by a person who signs in (Flow account): 3 contacts x 100 messages each, no expiry, one allowance per person shared by every app they claim (up to 10). iMessage is in neither. Apps of your own Flow account (made in the dashboard or by `npx @flow-engineer/flow setup`) get the free trial instead, started at your first sign-in: 25 people per channel, across all the account's apps, on Flow's shared Telegram bot and iMessage line (and on WhatsApp's shared sender when it opens), and `GET /v0/app` shows no `allowance`. Only messages your agent sends count. Simulated conversations (`POST /v0/test/conversations`, test keys) are free: they take no contact slot and no messages, so test as much as you like on the app you have; tell them apart by `simulated: true` on the conversation, the contact and the event's `conversation`. To keep the app, a person signs in with a Flow account (flow.engineer: Google, GitHub or an email link): run `npx @flow-engineer/messaging login --no-wait`, show them the link and code it prints (they open the page, sign in and type the code), and after they approve run `npx @flow-engineer/messaging login` (it replaces `FLOW_MESSAGING_KEY` in `.env` and drops `FLOW_CLAIM_TOKEN`). Past the allowance, sends fail with `403 permission` and `channel_code` `sandbox_allowance_used`, `sandbox_contact_limit`, `sandbox_channel_not_included` or `sign_in_required`; an expired key is `401 authentication` with `sandbox_key_expired`. Do not retry or get more keys: on a sandbox app, ask the person to sign in. On a full free trial a send to a held person answers `403 permission`, `sandbox_contact_limit`: delete a contact you no longer need (`DELETE /v0/contacts/{contact_id}` with the key of the app and mode they joined; the oldest held person gets the place), or have the workspace owner buy Shared at https://flow.engineer/dashboard/plans?plan=shared. On a full Shared plan (`plan_people_limit`) wait for the UTC day or month, delete a contact, or move to Dedicated at https://flow.engineer/dashboard/plans?plan=dedicated. `plan_ended` (`401 authentication` for a live key, `403 permission` for a live send): the paid plan ended and live keys are paused; the workspace owner chooses a plan again at https://flow.engineer/dashboard/plans, and test keys keep working.

```ts
import { FlowMessaging, contentText } from "@flow-engineer/messaging";
const flow = new FlowMessaging();
for await (const event of flow.events.stream({ types: ["message.received"] })) {
  await event.conversation.reply(myLlmStream(contentText(event.data.message.content)));
}
```

- Type handlers with `FlowEvent` / `FlowEventOf<"message.received">` (its `conversation` can `reply`), not `Event`.
- `reply` takes a string, a message of any kind, or an LLM stream (OpenAI, Anthropic, Vercel AI SDK,
  OpenAI Agents, Claude Agent SDK, LangChain, Mastra) and sends it as chat bubbles.
- Webhooks: `flow.webhooks.handler({ secret, onEvent })` for Request/Response
  frameworks, or `await flow.webhooks.constructEvent(rawBody, signature, secret)`.
- Reply into a conversation; never choose a channel per message. Contacts may have no phone number.
- iMessage replies only (the person writes first) unless a dedicated line can write first (the Outbound add-on, bought by the workspace owner at https://flow.engineer/dashboard/plans?plan=dedicated). iMessage has no 24-hour window: once someone has texted your line, your agent can message them any time. Flow's shared iMessage line comes with the free trial a sign-in at flow.engineer (or `npx @flow-engineer/flow setup`) starts, a free trial for 25 people on the shared iMessage line. Connect your own WhatsApp number with a live key (`POST /v0/senders`, `channel` `whatsapp`). a dedicated iMessage line comes with the Dedicated plan, bought in the dashboard (Settings → Usage and billing → Choose a plan); US SMS numbers (pilot) are connected by Flow (support@flow.engineer; never send secrets; build and test on Telegram meanwhile; the code is the same); on WhatsApp, outside 24 h needs a `template`. A kind or field the channel does not take fails with `422 unsupported_content` (its `hint` says what to send instead); nothing is converted.
- Errors are typed classes (`OutsideWindowError`, `UnsupportedContentError`, ...); retries are automatic.
- Local testing: `npx @flow-engineer/messaging listen --forward-to <url>`, `npx @flow-engineer/messaging send "hi"`.
- MCP server (optional, for development): `https://api.flow.engineer/mcp`, with the same key as a Bearer token. MCP is not a runtime dependency: the app you build talks to Flow through the REST API (or the TypeScript or Python SDK, which wrap it) for everything it does at runtime. Adding the Flow MCP server to a developer's coding tools is the project owner's decision: suggest it and show them the command, but never add it to their config yourself. For Claude Code the command is `claude mcp add --transport http flow https://api.flow.engineer/mcp --header "Authorization: Bearer $FLOW_MESSAGING_KEY"` (Codex and Cursor: section 12 of https://api.flow.engineer/docs/quickstart.md); `FLOW_MESSAGING_KEY` must be set when it runs (unset, the header is saved as `Bearer ` with no key), and the client loads a new server only after a restart. If its tools are already available to you, use them for sandbox testing; after a test send, wait for `message.sent` or `message.failed`.
- Flow Observe (early access) grades every conversation: no code on Flow Messaging. To see each turn's model and tool calls, export OpenTelemetry traces to https://flow.engineer/observe/v1/traces (`Authorization: Bearer $FLOW_OBSERVE_TRACE_KEY`) with `flow.conversation_id` and `flow.message_id` of the message being answered on the turn's span. https://flow.engineer/docs/unified-messaging-api/observe/traces.md
