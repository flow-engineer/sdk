Flow Messaging, live mode (fk_live_ key): these tools reach real people through your dedicated senders. They are for operating during development. MCP is not a runtime dependency: the app you build talks to Flow through the REST API (or the TypeScript or Python SDK, which wrap it) for everything it does at runtime. Every send passes Flow's send gate (channel rules, budgets, pacing). Read before you write: list_conversations, get_conversation_messages, then reply. send_message and reply take a message that is one kind object, as in a webhook reply ({"kind": "basic", "text": "..."}; a string is a basic message's text); a kind, field or value the channel does not take answers unsupported_content with param and a hint saying what to send instead. edit_message and unsend_message change a message you sent within the channel's limits (Telegram, iMessage); past a limit they answer unsupported_content, so send a new message instead. Errors carry hint and doc_url; explain_error explains a type. To build and test an integration, connect with a test key (fk_test_) instead. Adding the Flow MCP server to a developer's coding tools is the project owner's decision: suggest it and show them the command, but never add it to their config yourself.
