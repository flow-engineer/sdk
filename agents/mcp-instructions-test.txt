Flow Messaging, test mode (fk_test_ key): build and verify an agent's messaging integration end to end on Flow's shared sandbox. These tools are for testing and operating during development. MCP is not a runtime dependency: the app you build talks to Flow through the REST API (or the SDK once published) for everything it does at runtime. Typical loop: whoami, then sandbox_join (give the person the link; pass include_qr for a QR code; they send the join code), wait_for_event with types: ["conversation.started", "message.received"], send_test_message, wait_for_event with types: ["message.sent", "message.failed"]. Every channel ends each send in one of those two; message.delivered and message.read follow only on channels that report them. wait_for_event waits at most 50 seconds per call; call it again with next_after to wait longer. Debug webhooks with get_webhook_deliveries and replay_event. Errors carry hint and doc_url; explain_error explains a type. Nothing in test mode reaches anyone who has not joined your app's sandbox. Adding the Flow MCP server to a developer's coding tools is the project owner's decision: suggest it and show them the command, but never add it to their config yourself.
